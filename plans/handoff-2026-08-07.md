## The decision this session reached: kill Supabase

**Evidence gathered, not assumed.** Every app schema (`dm`, `house_ops`, `auxi`, `memory`) has
**zero rows**. Every tenant database (house_ops, common_ground, event_planner,
minecraft_companion, practice_exchange, work_ontology) has **zero rows**. `auth` holds 44,806
rows of session/audit churn and 18 users — 15 with no email, one `demo@dm.local`, one
`smoke@dm.jimr.fyi`, and Jim. **One real account, zero application data.** `_supabase`
(internal analytics) is 479 MB of the ~750 MB total.

So ~12 containers (Logflare, Studio, Kong, Supavisor, PostgREST, Storage, Realtime, edge
functions, imgproxy, vector, meta, GoTrue) serve empty schemas. Replace with one plain
`postgres`. Jim has approved this.

**The prize: the GoTrue↔Zitadel federation disappears.** No rewrite shim, no identity-linking
rules, no UUID-preservation test — Phase 4 of the migration plan was machinery for protecting
data that does not exist. Delete it.

### Order of operations (matters — backwards breaks every gated route)

1. Create the OIDC application in Zitadel; point Pomerium's `idp_*` at it. Needs management-API
   access: re-init the instance with a bootstrap machine PAT
   (`ZITADEL_DEFAULTINSTANCE_ORG_MACHINE_MACHINE_USERNAME`, `..._PAT_EXPIRATIONDATE`, verified in
   `cmd/defaults.yaml`) — free, it holds no real identities.
2. Model access as Zitadel project roles; convert `land.jimr.fyi` from
   `authenticated_user: true` to a role claim. **Gate: remove the role → 403 after session
   refresh, with no converge.** That is the whole point of the migration.
3. Repoint Pomerium's databroker storage off the Supabase Postgres (10 rows of session state,
   worth nothing) onto the plain Postgres.
4. Tear down the Supabase stack. Keep one `postgres` container for future app data.
5. Delete the dead scaffolding: `gated`/`allowed_emails` in `vars.yml`, GoTrue references,
   the shim sections of the migration plan, the `platform-users` skill's GoTrue procedures.

### Verified facts worth not re-deriving

- Zitadel emits `email_verified` as a real JSON boolean (`zitadel/oidc` `type Bool bool`, no
  custom marshaler). Irrelevant now that federation is dead, but it was the gate.
- Pomerium reaches Zitadel over `h2c://` with `preserve_host_header` — combination documented by
  neither project. A wrong Host returns 404 "instance not found".
- Cloudflare's orange cloud does NOT break Connect-RPC: grpc-web POST returns 200 over HTTP/1.1.
- Zitadel's endpoints (`/oauth/v2/*`, `/oidc/v1/userinfo`) share nothing with the paths GoTrue's
  keycloak driver hardcodes.
- Compose network joins must be **declared**; an imperative `docker network connect` is lost on
  the next container recreate (cost an Envoy `no_healthy_upstream` debug).
- `auth.jimr.fyi` was already the OIDC portal page — the IdP is `id.jimr.fyi`.

## Orchestration advice (Jim asked)

**vps1 `10.0.0.5` and the platform VPS are the same machine** (10.0.0.5 is its WireGuard
address), and it already runs `genesis.service` and `agent-platform.service` under systemd
beside Docker Compose.

**Do not add K3s.** It would be a third orchestration model on a box whose two most important
workloads are deliberately single-instance stateful engines a scheduler does not help. Keep
Compose for infrastructure (Pomerium, Zitadel, Postgres) and systemd for the engines.

**Treat the common-ground container as a bridge.** The map is HTML because that is what existed;
the declared direction is factored-ui as the only UI, and `geomap` now renders parcel choropleths
natively. Keep the tenant container dumb so retiring it is free. Do not build a tenant platform.
